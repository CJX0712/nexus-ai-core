# NexusAI 部署指南

> 作者：晨星

---

## 1. 环境要求

| 项 | 最低 | 推荐 |
|----|------|------|
| Python | 3.11 | 3.13 |
| Node.js | 20 | 22 |
| 内存 | 4 GB | 8 GB |
| 磁盘 | 2 GB（含嵌入模型） | 5 GB |
| GPU | 不需要 | 有则本地推理更快 |

> 无 GPU 完全可用：嵌入走 ONNX CPU，本地推理走 GGUF 量化模型。

---

## 2. 三种部署方式

### 2.1 Docker Compose（推荐，一键起）

```bash
cp .env.example .env
docker compose up --build -d
docker compose ps          # 两个容器均应 healthy
```

| 服务 | 地址 |
|------|------|
| 控制台 | http://localhost:8080 |
| API | http://localhost:8000 |
| Swagger | http://localhost:8000/docs |

### 2.2 本地直跑（开发调试）

```bash
python -m venv .venv
. .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r backend/requirements.lock.txt
cd backend && python -m uvicorn app.api.main:app --reload --port 8000

cd frontend && npm install && npm run dev    # http://localhost:5173
```

前端 dev server 已配置代理，`/v1`、`/health`、`/docs` 自动转发到 8000 端口。

### 2.3 生产部署要点

- 用 `gunicorn`/`uvicorn workers` 或多副本容器承载后端；向量库与记忆库挂载持久卷（`./data`）
- 在反向代理层限制 `/v1/*` 的速率，避免模型调用被刷
- 设置 `NEXUS_ENV=production`，关闭 `--reload`
- 前端 `npm run build` 后由 Nginx 托管（`frontend/nginx.conf` 已含反向代理配置）

## 3. 环境变量

全部变量均可选，未配置时自动降级。完整清单见 `.env.example`。

| 变量 | 默认 | 说明 |
|------|------|------|
| `NEXUS_LLM_PROVIDER` | `auto` | `auto`/`openai_compat`/`llama_cpp`/`offline` |
| `NEXUS_LLM_BASE_URL` | 空 | OpenAI 兼容端点根地址 |
| `NEXUS_LLM_API_KEY` | 空 | 云端 API Key |
| `NEXUS_LLM_MODEL` | 空 | 模型名，如 `deepseek-chat` |
| `NEXUS_LOCAL_GGUF_PATH` | 空 | 本地 GGUF 模型路径（llama.cpp） |
| `NEXUS_EMBED_PROVIDER` | `auto` | `auto`/`fastembed`/`openai_compat`/`hashing` |
| `NEXUS_EMBED_MODEL` | `BAAI/bge-small-zh-v1.5` | 嵌入模型 |
| `NEXUS_DATA_DIR` | `./data` | 向量库与记忆库落盘目录 |
| `NEXUS_TOP_K` | `4` | 检索返回条数 |
| `NEXUS_CHUNK_SIZE` / `OVERLAP` | `512` / `64` | 分块大小与重叠 |
| `NEXUS_HYBRID_ENABLED` | `true` | 是否启用 BM25 混合检索 |
| `NEXUS_AGENT_MAX_STEPS` | `6` | 智能体最大步数 |
| `NEXUS_MEMORY_MAX_TURNS` | `20` | 短期记忆保留轮数 |

## 4. 部署后验证

```bash
# 1) 健康检查
curl http://localhost:8000/health
# 期望：{"status":"ok", ...}

# 2) 入库
curl -X POST http://localhost:8000/v1/rag/ingest -H "Content-Type: application/json" \
  -d '{"text":"NexusAI 由模型网关、知识检索、智能体编排、工作流引擎、记忆五个模块组成。","source":"arch.md"}'

# 3) 溯源问答
curl -X POST http://localhost:8000/v1/rag/ask -H "Content-Type: application/json" \
  -d '{"question":"NexusAI 由哪些模块组成？","top_k":3}'

# 4) 工作流
curl -X POST http://localhost:8000/v1/workflow/run -H "Content-Type: application/json" \
  -d '{"input":"模块化","nodes":[{"id":"a","kind":"transform","params":{"template":"主题:{input}"},"depends_on":[]}]}'
```

## 5. 备份与回滚

| 操作 | 命令 |
|------|------|
| 备份知识库与记忆 | `tar czf nexus-backup.tgz data/` |
| 恢复 | `tar xzf nexus-backup.tgz` |
| 回滚镜像 | `docker compose down && git checkout <上一版本 tag> && docker compose up --build -d` |
| 清空知识库 | 删除 `data/index/faiss.index` 与 `data/index/meta.json` 后重启 |

## 6. 常见问题

| 现象 | 原因 | 处理 |
|------|------|------|
| `/health` 中 `embedding_provider=hashing` | fastembed 模型下载失败或首次使用未就绪 | 联网后重启；或显式设 `NEXUS_EMBED_PROVIDER=fastembed` 观察日志 |
| 回答带 `[offline-extractive]` 前缀 | 未配置可用的 LLM | 配置 `NEXUS_LLM_BASE_URL` + `API_KEY` + `MODEL`，或放置本地 GGUF |
| 上传文件报 400 | 扩展名不支持或文件无文本层 | 仅支持 txt/md/pdf/docx/html；扫描版 PDF 需先 OCR |
| 首次启动较慢 | fastembed 需下载 ONNX 模型（约 90 MB） | 等待一次即可，后续走本地缓存 |
| 端口被占用 | 8000/8080 已占用 | 改 `docker-compose.yml` 端口映射或 `NEXUS_PORT` |
