# NexusAI 系统架构

> 作者：晨星 · 版本 v1.0.0

---

## 1. 设计原则

| 原则 | 落地方式 |
|------|----------|
| 单一职责 | 每个模块只做一件事；职责边界写进模块 docstring |
| 依赖倒置 | 模块不互相 `new`，依赖通过构造函数注入 |
| 唯一装配点 | 只有 `app/container.py` 做依赖装配 |
| 契约先行 | API 由 Pydantic 模型定义，自动生成 OpenAPI 3.0 |
| 可独立验证 | 每个模块都有可脱离其他模块运行的单元测试 |
| 优雅降级 | 无 Key / 无网络 / 无 GPU 时链路仍不中断 |

## 2. 模块划分与接口契约

### M1 模型网关 `app/gateway/`

单一职责：屏蔽 provider 差异，只负责"对话补全"与"文本嵌入"。

```python
class LLMProvider(Protocol):
    name: str
    def complete(messages, *, temperature, max_tokens) -> ChatResult: ...

class EmbeddingProvider(Protocol):
    name: str
    dim: int
    def embed(texts: list[str]) -> np.ndarray: ...   # 行已 L2 归一化
```

三级降级链（`auto` 模式）：

```
云端 OpenAI 兼容 API  →  本地 GGUF(llama.cpp)  →  离线抽取式应答
        (质量最高)            (离线可用)              (永远可用)
```

嵌入降级链：`fastembed(ONNX)` → `OpenAI 兼容 /embeddings` → `哈希嵌入(零依赖)`。

### M2 知识检索 `app/rag/`

单一职责：把文档变成可检索片段，并给出带溯源的答案。

```
loaders（解析） → chunker（递归分块+重叠） → embeddings（向量化）
    → FaissVectorStore（稠密）  ┐
    → BM25（稀疏）              ┘→ HybridRetriever（RRF 融合） → RAGService
```

- 稠密检索：FAISS `IndexFlatIP` + 归一化向量 ⇒ 内积即余弦
- 稀疏检索：BM25Okapi，中文按单字+二元组分词
- 融合：RRF，记分 `1/(k + rank)`，默认 k=60

接口：`ingest_text()` / `ingest_file()` / `search()` / `answer()` / `stats()`

### M3 智能体 `app/agent/`

单一职责：控制"推理-行动-观察"循环。

- `ToolRegistry`：工具注册与调用，描述为 JSON Schema（可直接映射 MCP / function-calling）
- `ReactAgent`：解析模型输出中的 `Thought / Action / Action Input / Final Answer`
- 健壮性：模型不按格式输出时当作最终答案；工具异常转为 Observation；超出步数上限强制收尾

内置工具：`rag_search` / `calculator`（字符白名单，禁止代码执行）/ `now` / `memory_recall` / `memory_remember`

### M4 工作流 `app/workflow/`

单一职责：DAG 的拓扑调度与节点执行。

节点类型：`transform`（模板渲染）/ `rag`（检索）/ `tool`（工具调用）/ `llm`（生成）
调度：Kahn 拓扑排序，检测环、重复 id、缺失依赖并抛 `WorkflowError`
上下文：节点输出写入 `ctx[node_id]`，下游用 `{node_id}` 占位符引用

### M5 记忆 `app/memory/`

单一职责：会话记忆的写入、读取、召回。
短期：进程内环形缓冲；长期：SQLite 落盘，支持关键词 `LIKE` 召回。

### M6 API 服务 `app/api/`

单一职责：HTTP 装配与错误映射。分层：`routes/ → 模块服务 → 网关`。
所有领域错误继承 `NexusError`，统一转为结构化 JSON（含 `code` / `message` / `detail`）。

### M7/M8 控制台与可观测

前端：React + TS，所有颜色来自 `tokens.css` 变量，图标统一 lucide 描边 SVG（不使用 emoji）。
可观测：`/health` 暴露各模块装配状态，`/v1/stats` 暴露系统自描述。

## 3. 数据流（一次带溯源的问答）

```
1. POST /v1/rag/ask  {question}
2. RAGService.search → HybridRetriever（向量+BM25，RRF 融合）→ top_k 片段
3. RAGService.build_context → "[1] source=xxx\n片段正文"
4. 组装 messages = [system, user([CONTEXT]...[/CONTEXT] + question)]
5. LLMGateway.complete → 按降级链取第一个可用 provider
6. 返回 {answer, provider, model, sources[], latency_ms}
7. （/v1/chat 路径额外）写入 MemoryStore：user 与 assistant 各一条
```

## 4. 关键设计决策（ADR 摘要）

| 编号 | 决策 | 理由 | 代价 |
|------|------|------|------|
| ADR-001 | 用 FAISS 而非外部向量数据库服务 | CPU 可跑、进程内嵌、零运维，干净环境一键复现 | 缺少分布式能力，后续可换 Qdrant |
| ADR-002 | 用 fastembed 而非 sentence-transformers | ONNX 推理，**不需要 torch**，安装体积与复杂度大幅下降 | 模型选择面略窄 |
| ADR-003 | 稠密+稀疏混合检索 | 纯向量易漏关键词精确命中，RRF 融合兼顾两者 | 需维护 BM25 索引 |
| ADR-004 | 自建精简 OpenAI 兼容适配层 | 主流厂商协议已趋同，避免引入重型网关依赖 | 不覆盖非 OpenAI 协议的私有 API |
| ADR-005 | 提供离线抽取式兜底应答 | 保证"构建即可运行、运行即可验证"，无 Key 也能演示全链路 | 离线答案非生成式，质量低于真实 LLM |
| ADR-006 | 依赖注入 + 单一组合根 | 模块可独立实例化与测试，避免循环依赖 | 需维护 container |
| ADR-007 | 前端不用 UI 框架、纯 CSS Token | 依赖最少、构建最快、颜色全部可控 | 组件需自行实现 |

## 5. 可验证性矩阵

| 模块 | 独立验证方式 | 测试文件 |
|------|--------------|----------|
| M1 网关 | 哈希嵌入确定性/归一化；降级链逐个失败 | `test_gateway.py` |
| M2 检索 | FAISS 增删查与落盘重载；RRF 排序单调 | `test_rag.py` |
| M3 智能体 | 脚本化假 LLM 驱动 ReAct，断言工具调用与步数上限 | `test_agent.py` |
| M4 工作流 | 拓扑序、环检测、上下文传递 | `test_workflow.py` |
| M5 记忆 | SQLite 落盘重载、关键词召回、会话隔离 | `test_memory.py` |
| M6 API | TestClient 覆盖全部端点与错误码 | `test_api_e2e.py` |
| 核心层 | 配置覆盖、分块边界、多格式解析 | `test_core.py` |
